# 复盘：这个项目上踩过的坑

> 写这份东西的目的不是自我批评，是**给下一次省时间**。每条都注明「现象 → 原因 → 以后怎么做」。
> 按性质分成七类：环境与沙箱、数据与协议、隐私脱敏、OCR、构建与打包、界面、流程。

---

## 0. 结论先行

如果只记五条，记这五条：

1. **能在用户浏览器里做的事，不要搬到服务端。** 教务 `jwxt.bistu.edu.cn` 的证书链不完整（只发叶子证书、不发 GlobalSign 中间证书），Node / curl / 任何服务端脚本都会 `UNABLE_TO_VERIFY_LEAF_SIGNATURE`；浏览器靠 AIA 自动补链所以用户毫无感觉。这一条直接决定了整个架构：**抓取放在书签小工具和壳的 WebView2 里，不做云端定时抓取。**
2. **网上找的同校脚本不能信。** 流传最广的那个北信科课表油猴脚本，节次时间表从 08:00 开始、第 5 节 11:30 —— 与本校现行作息**整整差一节课**。照抄就会给用户错误的提醒时间。所有事实以自己实测为准。
3. **测试要能红。** 脱敏脚本那次的教训最贵：它把 fixture 里的 `<a data-kblx="01" …>` 全洗掉了，而回归测试**照样全绿**——因为被测的那条分支再也不会被触发。凡是「洗干净了」的步骤，都要有一条**反向断言**（锚点还在不在）。
4. **看不见的产物不算做完。** APK 用 Gradle 增量构建会**在文件里留下几 MB 的死字节**（9.68 MB 的真实产物被写成 16.3 MB）。字节数、SHA256、条目数、`holes=0` 都得自己验。
5. **进程边界和数据边界是 bug 的高发区。** 大部分「玄学问题」最后都落在三处：日期字符串带的时分秒、`& exe` 拿不到 GUI 退出码、JSON 转义后的文本上做正则。

## 1. 环境与沙箱

| 现象 | 原因 | 以后怎么做 |
|---|---|---|
| PowerShell 5.1 和 `curl.exe` 都连不上 bistu 站点（`基础连接已经关闭`／`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`） | Windows 原生 TLS 栈（schannel）在本沙箱不可用 | **一律用 Node**（自带 OpenSSL），v24 起内置 `fetch` |
| `node --test test/` 报 `spawn EPERM` | 沙箱禁止命名管道，测试跑不起来子进程 | 改 `node test/run.mjs`，用 `node:test` 的进程内 API |
| Edge 无头模式直接崩（`mojo\public\cpp\platform\platform_channel.cc:187 Check failed: . : 拒绝访问`） | workspace-write 模式下不给建 mojo 平台通道 | 跑浏览器**必须** `sandbox_permissions: "danger-full-access"` |
| `& $edge --headless=new …` 退出码空、截图 0 字节 | `&` 调用会被这个会话的转发吞掉 | `Start-Process -FilePath $edge -ArgumentList @(…) -PassThru -Wait -WindowStyle Hidden`，且用完轮询等文件落盘 |
| 用 `--window-size=430,932` 截图，右侧内容被裁，但 CSS 看起来没错 | Windows 下 `--headless=new` 会建真窗口，有约 **500px 最小宽度**，`--window-size` 只决定截图宽度 | 要真窄屏视口就**套 iframe 探针页**（360/390/430 三列并排再整页截图） |
| `dotnet` 一启动就 `Access to the path 'C:\Users\lian3\.dotnet' is denied` | 首次运行配置器要写用户主目录 | 把 `DOTNET_CLI_HOME`、`NUGET_PACKAGES` 指到工作区内，并设 `DOTNET_SKIP_FIRST_TIME_EXPERIENCE=1` |
| `dotnet restore` 报 `NU1301 … The SSL connection could not be established` | 沙箱的 HTTPS 通道被拦 | 用 Node 从 `api.nuget.org/v3-flatcontainer/…` 下 `.nupkg`，建本地文件夹源 + `NuGet.config` 里 `<clear />` |
| `[Reflection.Assembly]::LoadFrom('<dll>')` 报 `HRESULT: 0x80131515` | 想反射查的是 .NET Core 程序集，PS 5.1 是 .NET Framework | 查 API 就去读 nupkg 里的 **`.xml` 文档**，别用 PS 反射 |
| `[IO.File]::ReadAllText('相对路径')` 报「未能找到文件」 | .NET 的 CWD 和 PowerShell 的 `cd` 不是一回事 | 一律用绝对路径 |
| `… | Select-Object -First N` 之后 `$LASTEXITCODE` 变成 1 | 截断原生命令管道会改变退出码语义 | 判断成败别套 `Select-Object`，或者另存退出码 |
| `& exe --uitest` 后 `$LASTEXITCODE` 为空、报告文件还读不到 | GUI 子系统的程序不通过控制台回传退出码，且写文件是异步的 | `Start-Process -PassThru -Wait` 取 `$p.ExitCode`，并**轮询**等报告文件出现 |
| `node -e "…${id}…"` 报 `SyntaxError: Unexpected token ':'` | PowerShell 双引号里会吃掉 `${…}` 和反引号 | 别用 `-e` 拼长脚本，写成 `.mjs` 文件再跑 |
| Gradle 官方源连不上；`MasterKey` 类不存在 | 官方分发被墙；JDK 里那叫 `MasterKeys` | 走华为云镜像；类名以实际 JDK 为准 |

## 2. 数据与协议

1. **老强智接口在本校全部 404。** 网上流行的 `app.do?method=authUser` / `getKbcxAzc` 那一套（`QZAPI` 等仓库）对本校完全无效 —— 本校是**新版强智 EMAP**（`/jwapp/sys/...`）。判据：`GET /jwapp/` 返回 `Welcome come to EMAP.`。**先判代际，再抄接口。**
2. **SSO 的 `flowKey` 不在页面里，在 cookie 里。** 它在 `COOKIE_INFO`（URL 编码的 JSON）中；不去读 cookie 就会一直拿到 `{"code":180040,"msg":"Flowkey未找到"}`。
3. **日期字段带时分秒。** `getTermWeeks` 返回 `"2026-09-07 00:00:00"`，一旦有人对着它做 `Number(v.slice(...))` 或字符串切分不当，就会得到 `'NaN-NaN-NaN'`。
   - 后果被放大：事件的 **UID 里含日期**，日期全变 NaN 后 22 门课**互相去重**，133 节课塌缩成 22 节。
   - 教训：**唯一标识里放什么，就要保证那个东西一定可解析**；并且在测试里断言事件总数，别只断言"跑通了"。
4. **`week` 是位图字符串，但长度随课程变化**（实测 2～17 位，等于该课最后一周），不是固定 19/20 位。按固定长度写循环就错。
5. **`weeksAndTeachers` 可以一门课多段多教师**：`"1-7周[讲授]/陈曦[主讲]; 1-7周[讲授]/古一[主讲]"`。全局 `split('/')` 后按奇偶取会让**第二段的周次串落进教师位**。正确做法：先按 `[;；]` 切段，再在段内按**最后一个** `/` 切。
6. **教室不能靠"剥掉 HTML 标签取最后一个词"。** `titleDetail` 里教师和地点都是 `<a>`，最后一个词往往是教师名（于是教室里出现了人名）。只认 `data-kblx="01"` 这个锚点（`02` 是教师）。
7. **`site` 登录页是 Vue 的 `v-model`。** 直接 `el.value = x` 不会更新 Vue 状态，提交上去还是空的；必须走原生 value setter 再 `dispatchEvent(new Event('input',{bubbles:true}))`。
8. **`ExecuteScriptAsync` 不 await Promise**，拿到的是 `{}`。要取异步结果必须走 CDP：`Runtime.evaluate` + `awaitPromise:true` + `returnByValue:true`。
9. **`file://` 下 Chromium 不给 `localStorage`。** 而内核靠 localStorage 存课表 —— 所以 WebView2 必须 `SetVirtualHostNameToFolderMapping` 把内核挂到一个虚拟 https 域上。

## 3. 隐私脱敏（最危险的一类，因为错了不会报错）

1. **不要在 `JSON.stringify` 之后的文本上做 HTML 正则。** 引号会被转义成 `\"`，`/<a data-kblx="02"[^>]*>/` 永远匹配不上，于是退化成"把所有 `<a …>` 一刀切成 `<a>`"——**属性全丢**，而依赖这些属性的回归测试变成**假绿**。
   - 正确做法：**在对象树上递归改**（对每个字符串值单独处理），改完再 stringify。
2. **不要只洗你以为的那一个数组。** 第一次只洗了 `datas.arrangedList`，结果同一个响应里 `datas.notArrangeList`（未排课）的教师名原样留在了 fixture 里。必须**递归遍历整棵对象树**。
3. **姓名白名单会漏。** 写死教师名单漏了只在 `weeksAndTeachers` 里以无方括号形式出现的一个人。改成从数据里自动抽取候选，再用更严的判据（长度、不含数字/标点/`周`/方括号、不在 `['讲授','实验','主讲',…]` 这类词表里）过滤。
4. **反向断言是必须的。** 洗完之后要断言：`data-kblx="01"` 和 `"02"` **仍然存在**、`[讲授]` **没被吃掉**、未排课条目数 **还是 5**、10 位学号与 `data-code=` 与真实姓名**一个都不剩**。没有这几条，脱敏脚本删多了也发现不了。

## 4. OCR（课表截图全自动识别）

1. **可行性先验证，再决定方案。** 先探针确认 `file://` 下单文件能跑 wasm + worker（走 Blob URL），确认能离线、能离网。
2. **不做任何预处理最好。** 灰度、二值化、放大、锐化我都试了 —— **原图彩色 + `tessedit_pageseg_mode: '11'`（SPARSE_TEXT）** 准确率最高（约 85%）。凭直觉加的预处理全是负收益。
3. **TSV 的 level 4（行）`text` 字段是空的。** 想拿整行文本必须在 level 5（词）上按 `(block_num, par_num, line_num)` 自己拼。
4. **行分组会跨列**：同一 y 上的两列会被并成一行（`中国近‖高等数`，`‖` 是竖线被识别成的字符）。**所以分列只能靠"词"的框**，不能靠行。
5. **`第N节` 标签贴在该行的顶部**，拿标签的 top 取中点当行边界会系统性偏移（实测只差 1.5px，但换个字体就崩）。
   - 稳健做法：**先把同一列里竖直相邻的词按"纵向间隙"聚成块，再拿整块归到某个节次带**。块内行距 19～31、块间间隙 304，阈值取 `max(中位字高 × 1.5, 12)` 就分得很干净。
6. **OCR 结果只当草稿。** 认完直接铺进格子让用户核对改错字，而不是假装准确。

## 5. 构建与打包

1. **`javascript:` 书签里不能有 `//` 注释。** 存书签 / 复制粘贴过程中一旦折行被吃掉，`//` 会把**后面全部代码**变成注释 —— 现象是"点书签完全没反应，且浏览器不报错"，极难查。
   - 做法：构建时只剥**整行**注释，并断言产物里**以 `//` 开头的行数为 0**；源码含反引号就直接报错（多行模板里可能有"看起来像注释"的内容，别做启发式猜测）。
2. **构建会清空 `dist/`。** 改完代码必须重跑构建 + 预览脚本，才能截图/验证，否则你看的是上一次的产物。
3. **把多个模块拼成一个文件时，顶层重名会静默出事。** 加一条 `assertNoDuplicates()`；同时加 `assertBrowserSafe()` 扫 `from 'node:` / `require(` / `Buffer` / `process.` / `__dirname` / `writeFileSync`，防止 Node 专用代码漏进浏览器产物。
4. **★ Gradle 增量 `assembleDebug` 会在 APK 里留下大块死字节。** 只改了注释、所有 task `UP-TO-DATE`，APK 却从 9,684,062 字节变成 **16,338,194 字节**。
   - 原因：打包器在原地重写 APK，内容压小之后**不截断**，旧内容以「洞」的形式留下（实测 `total holes = 6,654,132`，最大一条正好等于上一版 `assets/index.html` 的压缩大小）。
   - 做法：**先删掉旧 APK（或 `clean`）再 `assembleDebug`**。为此写了个零依赖的 `tools/apkinspect.mjs`（手写 zip 中央目录解析 + 本地记录遍历），一眼看出 `total bytes in holes between local records: 0` 才算干净。清理后：`9,684,066 字节 / 91 个条目 / gap to cdOff 4096（APK Signing Block 就在这个 gap 里）/ holes 0`。
5. **交付前要给出可核对的指纹。** 字节数 + SHA256，别只说"构建成功"。

## 6. 界面

1. **窄屏裁切要先证明是真 bug 还是伪影。** 第一轮截图看到"周日列被裁、底部标签被裁"，差点去改布局。证据是：`position:fixed; left:0; right:0` 的标签栏**也**超出了给定宽度，且每列实测 63px → `38 + 7×63 + 24 ≈ 503`。这是无头窗口 500px 最小宽度的伪影，不是布局问题。
   - 但顺手做了三处**真实**的健壮性修复：网格列改 `minmax(0, 1fr)`、卡片加 `min-width:0`（否则内部 `white-space:nowrap` 会把列顶宽、把页面撑出横向滚动条）、`#main` 加 `overflow-x:hidden`。
2. **加一个自查钩子。** `?debug=1` 时把视口宽 / `scrollWidth` / 网格 `scrollWidth` / 最宽元素写进 `document.title`。以后再有人报"手机上显示不全"，一眼定位。
3. **弹窗宽度要配得上内容。** 填课表的网格最窄需要 720px，而弹窗默认 `max-width:560px` —— 只能横向滚。加一档 `.wide`（860px）。

## 7. 流程与工程习惯

1. **先写"红"的证据。** 每个缺陷修复都先跑出一条失败的测试或一条真实的错误输出（`ERR_MODULE_NOT_FOUND`、`NaN-NaN-NaN`、`CS0246`），再改代码。没有红过的绿不算绿。
2. **用真实数据做 fixture，但洗过。** 真实响应能暴露一大堆纸面推演想不到的东西（日期带时分秒、位图长度不定、地点为空、多段多教师）。洗的时候按第 3 节那几条纪律来。
3. **抽公共实现，别复制。** 抓取逻辑一度只存在于书签里；壳要用就得复制一份，两边必然漂移。改成 `shells/capture.js` 是**唯一实现**，书签、Windows 壳、Android 壳都从它来。
4. **分离"能自动化的"和"必须问人的"。** 侦察阶段先确认 `info-query` 返回 `captcha:null` + `mfa:null` —— 确认「登录可以 100% 程序化」之后，整个自动刷新方案才成立。反过来，如果当初先写代码再发现要过滑块，就白做了。
5. **凭据纪律。** 侦察用的账号口令只用于验证链路，**绝不写进任何项目文件、日志、记忆或仓库**；真实服务里每个用户自己输入自己的。
